# Security policy

## Reporting a vulnerability

**Please do not open a public issue for a security problem.** Report it
privately through GitHub:

> **https://github.com/mayouni/stzlib/security/advisories/new**
> (the repository's *Security* tab, then *Report a vulnerability*)

The report is visible only to you and the maintainers, the discussion and
the fix happen in a private advisory, and the advisory is published --
with a CVE when one is warranted -- once the fix ships. If you cannot use
GitHub, open a public issue that says only "security contact requested",
with no detail, and we will reach you privately.

Include what you found, where (file and line, or the call that shows it),
how to reproduce it, and what an attacker gains. A proof of concept helps;
it is not required.

## What we promise

- **Acknowledgement within 72 hours** of your report, with a named person
  handling it.
- An **assessment within 7 days**: whether we confirm it, how severe we
  judge it, and the fix plan.
- **Coordinated disclosure.** We fix first and publish after, and we agree
  the date with you. We aim to ship a fix within 90 days of the report,
  sooner for anything actively exploited, and we credit you unless you ask
  us not to.
- If a vulnerability is **actively exploited**, we treat it as the EU Cyber
  Resilience Act requires of a manufacturer: an early warning within 24
  hours of becoming aware, a notification within 72 hours. The procedure is
  `libraries/stzlib/base/security/SOFTANZA_CRA_RUNBOOK.md`.

## Scope

In scope: everything in this repository, and in particular

- the Zig engine, `libraries/stzlib/engine/src/` -- TLS (`reactor.zig`),
  process spawning (`system.zig`), the SQLite layer (`db.zig`), crypto
  (`crypto.zig`), the security ledger (`seclog.zig`), model loading
  (`neural_embed.zig`, `model_digest.zig`);
- the security and governance planes, `libraries/stzlib/base/security/`
  and `libraries/stzlib/base/governance/`, and the agent-governance checks
  in `base/meta/stzGovernanceChecks.ring` and `base/agentic/`;
- anything that parses untrusted input: HTTP framing, JSON, XML, CSV,
  GGUF files, prompts built for a language model.

Also in scope, and welcome: a way for text that reaches a language model to
make an agent act beyond its granted capabilities. That boundary is a design
claim of this library, and a break in it is a vulnerability.

**Vendored libraries** (`libraries/stzlib/engine/vendor/`, listed with
versions in `sbom.cdx.json`): report upstream as well. Tell us too -- we
ship them, so their vulnerability is ours to patch.

Out of scope: the test fixtures under `base/test/` (throwaway keys and
certificates are there on purpose, and marked as such), and denial of
service that needs the attacker to already control the machine.

## Supported versions

Softanza has not published a release yet. Security fixes land on `main`,
which is the supported version, mirrored on GitHub and Codeberg. Once
releases exist, this section will name the ones that receive fixes.

## What the repository carries to help you

- `sbom.cdx.json` -- a CycloneDX software bill of materials of the vendored
  code, generated by `libraries/stzlib/engine/tools/sbom.py`;
- `libraries/stzlib/base/test/security/` -- the guards for fixed
  vulnerabilities. Each one failed against the code before its fix.
