# نموذج تحسين

*الرياضيات · الفصل 12 · المهارة FO-04: «هل أستطيع أن أقول ما أريد وأدع المحرك يقرر كيف؟»*

> ترجمة أولية، في انتظار مراجعة متحدث أصلي.

للقرار ثلاثة أجزاء: الأعداد التي يمكنك اختيارها، وما تريد أكثره، وما يجب أن تبقيه تحت حد. مكتوبة معًا تكون
نموذجًا، والنموذج يُحل لا يُحسب: يجد محرك أفضل اختيار ويقول كيف وجده. يكتب هذا الفصل النموذج نفسه مرتين،
كائنًا وجملة، ويتحقق من أنهما نموذج واحد، ويقرأ أفضل خطة ويفحصها يدويًا، ويلقى الرفضين اللذين يبديهما النموذج.

## 1. النموذج كائنًا

عددان يُختاران، x حتى أربعين وy عدد صحيح؛ عظّم ثلاثة x زائد اثنين y؛ أبقِ مجموعين تحت حديهما. اطلب من المحرك
حله.

```ring
oM = new stzOptimModel()
oM.Vars([ :x = [ 0, 40 ], :y = [ 0, :integer ] ])
oM.Maximize("3*x + 2*y")
oM.SubjectTo([ "x + y <= 50", "2*x + y <= 80" ])
oM.SolveWith(:auto)
? oM.StatusWord()
#--> optimal
? oM.Objective()
#--> 130
? @@( oM.Solution() )
#--> [ [ "x", 30 ], [ "y", 20 ] ]
```

## 2. المحرك يسمّي نفسه

يقول النموذج أي محرك عمل وما وجد. ثمة محرك واحد مبني اليوم، وتقول الجملة ذلك بدل التظاهر بأن هناك اثنين.

```ring
? oM.Why()
#--> Objective 130 at x = 30, y = 20
? oM.Engine()
#--> engine floor (Zig simplex + branch-and-bound)
```

## 3. أفضل خطة، مفحوصة يدويًا

الحل ادعاء. يفحص النموذج كل قيد مقابله ويبلّغ عن المخالفات، ويمكنك أن تفحص المجموعين والهدف بنفسك.

```ring
? @@( oM.Violations() )
#--> [ ]
? 30 + 20 <= 50
#--> 1
? 2 * 30 + 20 <= 80
#--> 1
? 3 * 30 + 2 * 20
#--> 130
```

## 4. النموذج نفسه جملةً

قل النموذج بكلمات فتبني المكتبة الكائن نفسه، عبر النداءات الثلاثة نفسها. سطحان، نموذج واحد: توقيعا بنيتهما
المجردة متساويان، وهذا يُفحص لا يُفترض، لأن نموذجين خاطئين قد يتفقان على عدد.

```ring
oS = StzOptimNaturally("
        maximize 3*x + 2*y
        where x is between 0 and 40
        and y is a whole number at least 0
        keeping x + y under 50
        and keeping 2*x + y under 80
     ")
? oS.ASTSignature() = oM.ASTSignature()
#--> 1
oS.Solve()
? oS.Objective()
#--> 130
```

## 5. النموذج، معادًا

اطلب من النموذج أن يصف نفسه فيقول الهدف والقيود والحدود التي يحملها.

```ring
? oM.Describe()
#--> max 3*x + 2*y
```

## 6. خطة إنتاج

الكراسي تكسب ثلاثين وتأخذ ساعتين؛ والطاولات تكسب خمسة وأربعين وتأخذ خمسًا؛ مئتان وخمسون ساعة وستون على الأكثر من
كل منهما. أفضل خطة ستون كرسيًا وست وعشرون طاولة، وطلب الأعداد الصحيحة يجعل المحرك يتفرع مرة.

```ring
oN = new stzOptimModel()
oN.Vars([ :chairs = [ 0, :integer ], :tables = [ 0, :integer ] ])
oN.Maximize("30*chairs + 45*tables")
oN.SubjectTo([ "2*chairs + 5*tables <= 250", "chairs <= 60", "tables <= 60" ])
oN.Solve()
? @@( oN.Solution() )
#--> [ [ "chairs", 60 ], [ "tables", 26 ] ]
? oN.Objective()
#--> 2970
? oN.Branched()
#--> 1
```

## 7. ما لا يمكن فعله

اطلب x عشرين على الأقل بينما لا يجوز لـ x أن يتجاوز عشرة، فيقول المحرك إن النموذج غير ممكن. هذا جواب، وهو
الصادق.

```ring
oF = new stzOptimModel()
oF.Vars([ :x = [ 0, 10 ] ])
oF.Maximize("x")
oF.SubjectTo([ "x >= 20" ])
oF.Solve()
? oF.StatusWord()
#--> infeasible
```

## 8. رفضان

طبقة محرك غير مبنية تُرفض بالاسم بدل أن تُستبدل بصمت، وجملة لا تستطيع المكتبة قراءتها دون تخمين تُرفض بدل أن
تُخمَّن.

```ring
try
	oM.SolveWith(:highs)
catch
	? "refused"
done
#--> refused
try
	StzOptimNaturally("maximize x where x is roughly 5")
catch
	? "refused"
done
#--> refused
```

## 9. على عالمك

موظفان يتقاسمان طلبات هذا الأسبوع في مدرستك: لكل منهما أن يأخذ الأسبوع كله على الأكثر، ويريد المكتب أكبر عدد
من الطلبات المعالجة. ما يطبعه يتوقف على العالم الذي يجري عليه هذا الدرس، ولذلك لا تعرض الصفحة أي نتيجة: شغّله.

```ring
aReq = EduWorldObjects("requested")
nR = len(aReq)
oW = new stzOptimModel()
oW.Vars([ :a = [ 0, :integer ], :b = [ 0, :integer ] ])
oW.Maximize("a + b")
oW.SubjectTo([ "a + b <= " + nR, "a <= " + nR, "b <= " + nR ])
oW.Solve()
? EduWorldName()
? oW.Objective()
```

## الخلاصة

- **ما أنجزته:** كتبت قرارًا نموذجًا، وحللته، وقرأت رواية المحرك نفسه، وفحصت أفضل خطة يدويًا، وكتبت النموذج
  نفسه جملة ورأيت الاثنين يتفقان بنية مجردة واحدة، وخططت إنتاجًا، ولقيت نموذجًا غير ممكن ورفضين.
- **لماذا يهم:** القرار المكتوب نموذجًا يقول ما يريد وما يجب أن يبقيه، ولا شيء عن الكيف. يجد المحرك أفضل خطة،
  ويسمّي نفسه، والخطة ادعاء يمكنك فحصه.
- **ما التالي:** نظرة توكي الأولى إلى البيانات، حين يُبنى مستوى توكي. وبعدها، المشتقة التي تفحص صيغة.
