### اللغز 10 · ضرب مصفوفتين بالبلاطات

> ترجمة مؤقتة، في انتظار مراجعة قارئ ناطق بالعربية.

`a` مصفوفة 32 x 64 و`b` مصفوفة 64 x 48، صفا بعد صف. اكتب `c = a x b`، بحجم 32 x 48:
`c[row][col]` هو مجموع `a[row][j] * b[j][col]` على j. القيم الثابتة تقول الشكل: `k` = 64 الطول
الداخلي، و`w` = 48 عرض `b` و`c`.

`width w` يجعل المخرج مصفوفة تعالج **ببلاطات 16 x 16**: كل مجموعة من 256 خيطا تحسب بلاطة واحدة من
`c`، ويسمي الخيط خانته بـ`@row` و`@col`، وموضعه داخل البلاطة بـ`@lx` (العمود 0-15) و`@ly` (الصف 0-15).

الطريقة البسيطة صحيحة وبطيئة: كل خيط يقرأ 64 عددا من `a` و64 من `b` من الذاكرة. طريقة البلاطات
تدور `tiles t { k / 16 }` مرة؛ في كل دورة تضع المجموعة بلاطة 16 x 16 من `a` وأخرى من `b` في
ذاكرتها، ويجمع كل خيط ستة عشر حاصل ضرب من هناك. كل عدد يقرأ من الذاكرة مرة لكل مجموعة بدل مرة
لكل خيط. نقطة البداية تضع بلاطة `a`:

    stage { @ta[@ly * 16 + @lx] = @a[@row * k + t * 16 + @lx] }

اكتب بلاطة `b` (الصف `t * 16 + @ly`، العمود `@col`)، ثم

    accumulate { @acc = @acc + sum(j, 0, 16, @ta[@ly * 16 + j] * @tb[j * 16 + @lx]) }
    body { @c = @acc }

`@acc` هو المجموع الجاري للخيط، يبقى من دورة إلى أخرى. دُر مرة واحدة فقط فيكون لكل خانة أول ستة
عشر حاصل ضرب فقط: *mismatch at element 1*. الشكل المخفي مصفوفة أخرى، 16 x 80 في 80 x 32، فالنواة
التي تحفظ 64 و48 تفشل هناك.

**ما فعله معالج الرسوميات على خلاف الحلقة:** الحلقة تحسب خانة بعد خانة. هنا حسبت 256 خانة معا،
وجلبت الأعداد التي تحتاجها كلها مرة واحدة، معا.
