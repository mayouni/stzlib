## The app server

**Closed-loop, one client**: the next request is sent only after the previous answer arrived, so queueing is not exercised and this is a round trip, not a capacity. Client and server share one process and one machine, so a request's time includes the client's own cost. The route answers a short text. An open-loop run is not made here and is not implied.

Three runs, each its own process, shown side by side and never pooled or reduced to one: the same code on this machine has given a p50 near 5 ms in some runs and near 31.6 ms, twice the Windows timer quantum of 15.6 ms, in others, so one figure would be a coin toss.

## What this does not say

- No other framework, no multiple, no ranking: parity of output is the only comparison made, and only between this library's own runs.
- One machine and one afternoon, with other sessions running; the ambient CPU above is the honest size of that.
- Inputs (the rows, the parsed panel, the run chapter) are built once and are not in the time.
- Resident set includes the library and engine loaded into the process; it is not the cost of one page.
