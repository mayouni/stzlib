Tidewater 2.4 Release Notes

A command-line tool for syncing project folders across machines

Tidewater 2.4 adds resumable transfers, a faster change scanner and a new configuration format. This document explains how to install the release and what changed since version 2.3.

Installation

1.Download the archive for your platform and unpack it into any folder.
2.Add the folder to your PATH.
3.Check the installation by running the command below.
tidewater --version
# tidewater 2.4.0 (build 5817)

Configuration

Example configuration file

The configuration file lives in the project root and is read every time the tool starts.

sync:
  source: ./project
  target: //nas01/backup/project
  exclude:
    - "*.tmp"
    - ".cache/"
retry:
  attempts: 5
  delay_seconds: 30

Options

OptionTypeDefaultDescription
sync.sourcepath.Folder to read changes from
sync.targetpathnoneDestination folder or network share
sync.excludelist[]Patterns that are never copied
retry.attemptsinteger3Number of tries before a transfer fails
retry.delay_secondsinteger10Pause between two tries

What is new

  • Resumable transfers: an interrupted copy continues where it stopped.
  • A change scanner that is about three times faster on large folders.
  • A new configuration format based on YAML.
  • Clearer error messages that name the file and the reason.

Breaking changes

–The old .ini configuration file is no longer read.
–The flag --dry is now called --preview.
–Exit code 4 now means a partial transfer and not an error.

Command reference

CommandPurpose
tidewater syncCopy new and changed files to the target
tidewater statusList files that differ from the target
tidewater resumeContinue the last interrupted transfer

Running a preview

Use the preview flag to see what a sync would do without copying anything.

tidewater sync --preview
3 files would be copied, 1 file would be removed

Known issues

1.Paths longer than 260 characters are skipped on older Windows versions.
2.The status command may report a file twice if it is renamed during a scan.

Report problems on the project tracker and include the output of the status command.
