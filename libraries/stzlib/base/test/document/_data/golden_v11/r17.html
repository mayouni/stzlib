Runbook RB-112: Rolling upgrade of parcel-router

Serviceparcel-router
Last reviewed2026-10-12
ApproverChange Advisory Board
RiskMedium

PURPOSE

This runbook describes how to upgrade parcel-router to a new release without interrupting label printing at the depots. Follow every step in order and record the result in the change ticket.

PREREQUISITES

  • An approved change ticket with a maintenance window of at least 60 minutes.
  • Access to the ops-bastion host and to the deploy role in the cluster.
  • The release notes for the target version, including any database migrations.

ENVIRONMENT

VariableExamplePurpose
ROUTER_IMAGE_TAG4.18.2Release to deploy
ROUTER_MAX_UNAVAILABLE1Pods replaced at a time
ROUTER_DRAIN_SECONDS45Time allowed to finish in-flight requests
ROUTER_DB_MIGRATEfalseRun migrations before the rollout

PROCEDURE

  1. Open a session on the bastion host and confirm the release that is currently running.
ssh ops-bastion
kubectl -n routing get deploy parcel-router \
  -o jsonpath='{.spec.template.spec.containers[0].image}'
  1. Update the production values file with the new image tag.
router:
  image:
    repository: registry.harbourline.example/parcel-router
    tag: "4.18.2"
  rollout:
    maxUnavailable: 1
    drainSeconds: 45
  resources:
    requests:
      cpu: 500m
      memory: 768Mi
  1. Apply the change and follow the rollout until every pod reports ready.
helm upgrade parcel-router ./charts/parcel-router \
  -n routing -f values/prod.yaml --atomic --timeout 15m
kubectl -n routing rollout status deploy/parcel-router
  1. Announce the completion in the operations channel and update the change ticket.

VERIFICATION

Print a test label from the Kelby depot console and check that the route code matches the postcode. Watch the error rate on the routing dashboard for fifteen minutes after the rollout.

  • HTTP 5xx rate below 0.5 percent.
  • Median label latency below 300 ms.
  • No pods in CrashLoopBackOff.

ROLLBACK

If the error rate rises above two percent, roll back immediately with the command below.

helm rollback parcel-router 0 -n routing --wait

Rollback does not revert database migrations, which must be handled together with the release team. Record the incident number in the change ticket before closing it.
