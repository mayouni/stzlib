# golden_v13 — 24 realistic PDF documents with known structure

An independent golden test set for scoring document readers (layout, reading order, headings, tables, lists, page furniture, code blocks, languages). Each document `uNN` comes as three files:

- `uNN.html` — the source page, the single authority for what is printed;
- `uNN.pdf` — that page printed by headless Chrome (A4, no browser header or footer);
- `uNN.expected.json` — the expected structure: `id, difficulty, pages, title, headings, key_sentences, tables, list_items, furniture, languages, code, notes`.

## How it was made

- Every document is a whole document of a kind real organisations produce (invoice, discharge summary, lease, school report, gazette notice, guide, quarterly report, receipt, NGO report, minutes, bulletin, timetable, booking confirmation, preprint, festival programme, parish bulletin, league report, policy schedule, electricity bill, waybill, maintenance report, mining report, tariff leaflet, IT instruction). All organisations, persons, addresses, numbers and references are fictitious; place names are real or invented.
- Each document was authored ONCE as a small Python program that emits the HTML and records, through the same calls, the headings, tables, lists, furniture, code and body sentences that go into `expected.json`. The HTML and the golden therefore cannot drift apart. Merged table cells are expanded into every grid cell they cover. `pages` is counted afterwards from the raw PDF bytes (`/Type /Page` objects and the `/Count` of the page tree).
- `key_sentences` are picked mechanically and evenly (at most 8, or 10 for u14) from the sentences of body paragraphs, in reading order; a sentence carrying a footnote marker is never picked, nor are fragments that end in a colon or comma, labels, sign-off lines or signature lines. Sentences inside table cells and list items are not key sentences.
- Rendering: `chrome.exe --headless=new --disable-gpu --no-pdf-header-footer --user-data-dir=<scratch profile> --print-to-pdf=uNN.pdf file:///.../uNN.html` (Chrome 155). Two layout techniques are used: "flow" documents use `@page { size: A4; margin: ... }` and put running headers, footers and page numbers in CSS page-margin boxes (`@top-right`, `@bottom-center`, `counter(page)`, `counter(pages)`); "paged" documents (u02, u10, u15, u22) set `@page { margin: 0 }` and compose each A4 page in the body, with its header and footer placed on the page.
- Layout was checked without any PDF tool: a copy of each page with a small script was loaded in headless Chrome (`--dump-dom`) to confirm that no composed page overflows, that no furniture line wraps onto a second line, that furniture lines do not overlap, and that no table is wider than its container. Where a table is said to continue across pages (u07, u20), its position was estimated from the same screen layout to cross the page boundary clearly.
- Fonts: only fonts installed on the authoring machine (read from the Windows font registry). Variable fonts (Bahnschrift, Sitka, Segoe UI Variable) were avoided because Chrome embeds them without a `/BaseFont` name, and no text was given a weight its family lacks. After rendering, the `/BaseFont` names were read from the raw PDF bytes (object streams inflated with zlib, nothing else) and compared with the families each document names. A font that appears ONLY in the page-margin boxes of a document proves that those boxes were printed. Every document embeds exactly the families it names, with no fallback font and no Type 3 font. One fallback was found and removed while building: Perpetua Titling MT has no "Ł", so u16's masthead uses a word without it.
- **Independence.** The author of this set never ran, imported or opened any PDF-to-text or document-conversion tool, any PDF rasterizer, any reader's code or any reader's output, and never looked at golden_v1 to golden_v12. Nothing here was tuned against a reader.
- **Unperceived.** No person has looked at these PDFs yet; their visual correctness rests on the source and the layout checks above. A human look at the 24 PDFs is still owed.

## Conventions a scorer must know

- Texts are the visible text with whitespace runs collapsed to one space (non-breaking spaces count as spaces); code keeps its exact spacing and newlines. No automatic hyphenation is used, so no word is broken with a hyphen. Letter-spaced text (letterheads, some headings) is given as its plain words. Uppercase text is uppercase in the source.
- Right-to-left documents (u04 ar, u15 fa, u21 he) give all text in logical order, and table rows list the rightmost column first. u15 keeps ZERO WIDTH NON-JOINER (U+200C) inside words, as standard Persian spelling requires.
- `headings` start with the title at level 1. A letterhead, a masthead, box captions written as field labels, table header cells and form labels are not headings. Box headings that ARE headings are listed (u09, u11, u19, u20, u22).
- `tables`: header row(s) first; a two-level header gives two rows; merged cells repeat their text; section, subtotal and total rows are rows of the same table; a table continued across pages is ONE table with its header once (u07, u10, u15, u20). A key/value block printed as a table is a table without a header row. `caption` is the visible caption line (above or below) or null.
- `list_items` carry the marker when it is typed in the text ("1.", "a)", "–", "Besluit 2026-41:", "፩.", "أولاً:") and no marker when CSS draws it. Nested items have level 1.
- `furniture`: one entry per visible line of letterheads, mastheads, running headers and footers; a repeated line is listed once; page-number lines are listed once per page because their text differs.
- Side-by-side boxes or columns are read box by box, left box first (right box first in right-to-left pages); the notes of each document say where.
