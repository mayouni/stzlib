# golden_v5 -- independent PDF golden set (18 documents)

## What this set is

Eighteen office, school, clinic, NGO and public-administration documents, ids
`h01` to `h18`, each given as three files:

| file | content |
|---|---|
| `hNN.html` | the source, written by hand (h16 generated by a small script from the same data) |
| `hNN.pdf` | the source printed to PDF by headless Chrome |
| `hNN.expected.json` | what a document reader should recover: title, headings, key sentences, tables, list items, furniture, languages, code, notes |

The set is meant to score document readers (for example Docling and Softanza's
native PDF reader). All content is invented: no real persons, companies or
institutions. Addresses, phone numbers and register numbers are made up; IP
addresses use the documentation range 192.0.2.0/24 and e-mail domains end in
`.example`.

## How it was made

1. Each document was written as one HTML file with its own CSS. Documents
   with page furniture are built as fixed A4 pages (`@page { margin: 0 }`,
   one `div.page` of 210 x 296 mm per printed page, header and footer inside
   the page); the others flow with `@page` margins and let Chrome break pages.
2. Each HTML file was printed with
   `chrome.exe --headless=new --disable-gpu --no-pdf-header-footer --user-data-dir=<separate scratch profile> --print-to-pdf=<hNN.pdf> file:///<hNN.html>`.
3. The page count was read from the raw PDF bytes (`/Type /Page` objects,
   cross-checked with `/Count` of the page tree). For fixed-page documents a
   script loaded the HTML in headless Chrome and checked that no page's content
   box overflowed, so nothing is clipped.
4. `expected.json` was written from the SOURCE, never from the PDF:
   - headings = the `h1`..`h6` elements in document order (level = tag level);
   - tables = the `table` elements, with `rowspan`/`colspan` expanded so that a
     merged cell repeats its text in every grid cell it covers; header rows
     first; a table continued on a later page (h01) is merged into ONE table
     with the header row once;
   - list items = the `li` elements, level = nesting depth; markers drawn by
     CSS are absent, markers typed in the text (`a)`, `☐`, `[1]`, `D:`) are kept;
   - code = the `pre` elements, verbatim (CSS line numbers are not text);
   - furniture = the page header/footer texts, each once;
   - title, key sentences, languages and notes were written by hand, and a
     check confirmed that every key sentence occurs in the source's visible
     text, in reading order.
5. Text conventions: whitespace runs collapse to one space (non-breaking and
   soft hyphens included: NBSP counts as a space, U+00AD is dropped), ligatures
   are given as letters, a word hyphenated at a line end is given whole,
   right-to-left text is in logical order, and sentences carrying a footnote
   marker are left out of `key_sentences`.

## Independence

The author of this set never ran, imported or opened any PDF-to-text or
document-conversion tool, any PDF rasterizer, any reader's code or any reader's
output, and never looked at golden_v1 to golden_v4. The PDFs were only
produced, sized and page-counted from their raw bytes. The expectations come
from what the author put into the HTML sources. (Screenshots of the HTML
sources themselves were taken in Chrome to check the layout.)
