1. Purpose

This runbook describes how to replace the server certificates used by the production PostgreSQL clusters before they expire. Certificates are issued by the internal certificate authority and are valid for 90 days.

2. Prerequisites

  • Membership of the db-operators group in the access portal.
  • A workstation with the cluster CLI version 2.8 or later.
  • An approved change request in the change calendar.
  • Confirmation that no backup job is running on the target cluster.

4. Procedure

4.1 Check the current certificate

Run the following command from your workstation and note the expiry date shown in the output.

openssl s_client -connect db-a-01.int.cwhn.example:5432 \
    -starttls postgres </dev/null 2>/dev/null \
  | openssl x509 -noout -subject -enddate

4.2 Request a new certificate

Create a certificate signing request with the configuration file below, and keep the private key on the database host only.

[ req ]
default_bits       = 4096
prompt             = no
distinguished_name = dn
req_extensions     = san

[ dn ]
CN = db-a-01.int.cwhn.example
O  = Calderwood Regional Health Network

[ san ]
subjectAltName = DNS:db-a-01.int.cwhn.example, DNS:pgcluster-prod-a.int.cwhn.example

4.3 Install the certificate

  1. Copy the signed certificate to /etc/postgresql/tls/server.crt on each replica first.
  2. Set the file owner to postgres and the mode to 0600.
  3. Reload the configuration on each replica and confirm that replication is still streaming.
  4. Fail over to a replica, then repeat the steps on the former primary.

The cluster manager reads its TLS settings from the following file:

tls:
  enabled: true
  cert_file: /etc/postgresql/tls/server.crt
  key_file: /etc/postgresql/tls/server.key
  min_protocol: TLSv1.2
reload:
  strategy: rolling
  pause_between_nodes: 60s

4.4 Verify

Repeat the check from step 4.1 and confirm that the new expiry date is about 90 days in the future.

cwctl cluster status pgcluster-prod-a --show-tls

5. Rollback

If clients report handshake failures, restore the previous certificate from the backup directory and reload the configuration.

SSL error: certificate verify failedIntermediate certificate missing from the chainAppend the intermediate certificate

Replication lag above 30 sReplica reloaded during heavy write loadWait for the lag to recover before
moving to the next node
