Tidewater Sync 4.2 Release Notes

Version 4.2.0 · released 26 October 2026

Tidewater Sync 4.2 is a feature release that adds scheduled two-way synchronisation for object stores and retires the legacy XML job format. Existing 4.x installations can be upgraded in place once their job files have been converted.

Highlights

  • Two-way synchronisation for S3-compatible and Azure Blob targets, with conflict detection based on object version identifiers.
  • A scheduler built into the agent, so external cron entries are no longer required.
    • intervals from one minute to seven days
    • optional quiet windows during which no transfers start
  • Resumable transfers for files larger than 4 GB.
  • A new validate command that checks job files without contacting any target.

Upgrading

Before you upgrade

  1. Stop all running jobs and wait until the agent reports an idle state.
  2. Back up the configuration directory, including:
    1. the job definitions in jobs/
    2. the credential store secrets.db
  3. Install the 4.2 package over the existing installation.

Converting job files

Job files written in the XML format must be converted before the agent is restarted. The converter writes a YAML file next to each XML file and leaves the original untouched.

$ tidewater-sync convert --from xml --to yaml jobs/*.xml
$ tidewater-sync validate jobs/
$ tidewater-sync agent restart

Configuration

The following keys are new or have changed default values in this release.

KeyDefaultDescription
schedule.every1hInterval between two runs of the job. Accepts units m, h and d.
schedule.window(none)Quiet window in local time during which no new transfer starts.
targets[].two_wayfalseEnables two-way synchronisation for the target.
conflict.policykeep-bothWhat to do when both sides changed: keep-both, prefer-source or prefer-target.
retry.attempts3Number of retries for a failed transfer before the job is marked as failed.
retry.backofflinearDelay strategy between retries: linear or exponential.
transfer.chunk_size64MBSize of the parts used for resumable uploads.

A minimal job file using the new scheduler looks like this:

schedule:
  every: 15m
  window: "22:00-06:00"
targets:
  - name: archive-eu
    type: s3
    bucket: tw-archive-eu
    two_way: true
retry:
  attempts: 5
  backoff: exponential

Deprecations and removals

  • – The XML job format is no longer read by the agent.
  • – The --legacy-auth option has been removed; use access keys or managed identities instead.
  • – The Windows Server 2016 package is deprecated and will not be built after version 4.4.

Known issues

Two-way synchronisation does not yet preserve custom metadata on Azure Blob targets. A fix is planned for version 4.2.1. Until then, jobs that rely on metadata should keep one-way mode.

On systems with more than 64 processor cores, the agent may report an inflated transfer rate in its status output. The transfers themselves are not affected.
