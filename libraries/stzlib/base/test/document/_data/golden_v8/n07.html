Runbook: Deploying the Ledgerline Billing Service to Production

Owner: Billing Platform team · Last reviewed: 12 October 2026 · Expected duration: 45 minutes

1. Purpose

This runbook describes how to deploy a new release of the Ledgerline billing API to the production cluster. Follow the steps in order and record each completed step in the change ticket.

2. Prerequisites

  • An approved change ticket in the change calendar
  • Membership of the billing-deployers group
  • Helm 3.14 or later, and kubectl configured for the prod-eu-west context
  • A green build of the release tag in the CI pipeline

3. Pre-deployment checks

  1. Confirm that no billing run is in progress.
    • Check the Batch Jobs dashboard for active invoice runs.
    • If a run is active, wait for it to finish or postpone the deployment.
  2. Announce the deployment in the #billing-ops channel at least 15 minutes beforehand.
  3. Compare the rendered manifests with the running release:
export RELEASE=2026.10.3
kubectl config use-context prod-eu-west
kubectl -n billing get deploy ledgerline-api -o wide
helm diff upgrade ledgerline ./charts/ledgerline \
  -n billing -f values/prod.yaml --set image.tag=$RELEASE

4. Deployment

Run the upgrade with the atomic flag so that Helm rolls back automatically if the new pods fail their readiness checks.

helm upgrade ledgerline ./charts/ledgerline -n billing \
  -f values/prod.yaml --set image.tag=$RELEASE \
  --atomic --timeout 10m
kubectl -n billing rollout status deploy/ledgerline-api

The rollout normally completes within six minutes. Do not interrupt the command while it is waiting.

5. Configuration reference

The production values file sets the following options:

replicaCount: 6
image:
  repository: registry.internal.example/ledgerline-api
  pullPolicy: IfNotPresent
resources:
  requests:
    cpu: "500m"
    memory: 768Mi
  limits:
    memory: 1Gi
featureFlags:
  invoiceBatchV2: true
  legacyTaxEngine: false

Never edit values/prod.yaml directly on a workstation; changes must go through a reviewed merge request.

6. Verification

  1. Check that all six pods report Ready.
  2. Run the synthetic invoice test in the monitoring tool and confirm that it passes.
  3. Watch the error-rate panel for 15 minutes.

7. Rollback

If the error rate stays above 2% for more than five minutes, roll back to the previous revision.

helm history ledgerline -n billing --max 5
helm rollback ledgerline 0 -n billing --wait
