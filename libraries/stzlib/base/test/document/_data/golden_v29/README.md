# golden_v29 — 24 realistic PDF documents with known structure

An independent golden set for scoring document readers (Docling and Softanza's native PDF reader). Each document `pNN` has three files: `pNN.html` (the source), `pNN.pdf` (rendered from it) and `pNN.expected.json` (the structure a reader should recover).

## How it was made

- Written by one author in one session (2026-10-29). Every document is a whole, realistic document of a kind real organisations produce; all organisations, people, addresses, numbers and products are invented.
- Each document was written as a small Python generator that builds the HTML **and** the expected structure from the same strings (tables, lists, headings, key sentences, code), so the expected text is the text the HTML shows. The generator also checks that every expected string is present in the visible text of the HTML.
- Rendered with headless Chrome 156 (`--headless=new --disable-gpu --no-pdf-header-footer`, separate profile), CSS `@page` A4 (p17 is A4 landscape). Running headers, footers and page numbers are CSS page-margin boxes (`@top-*`, `@bottom-*`, `counter(page)`), so they are real page furniture; letterheads are in the body.
- Fonts: only fonts installed in `C:\Windows\Fonts`, none variable. Family names were read from each font's name table; every character of each document was checked against the cmap of the font it is set in (fontTools); code blocks use Consolas or Courier New.
- After rendering, page counts were read from the raw PDF bytes (`/Type /Page` objects and `/Count`) and the embedded fonts from the raw `/BaseFont` names. No document embeds a fallback font.
- Layout was checked by looking at screenshots of the HTML (screen rendering, not the PDF) and, for page-break claims, by measuring element positions in a screen layout of the same width (Chrome `--dump-dom`). Where a note says a table crosses a page break, that was measured.

**The author never ran a PDF-to-text extractor, conversion tool or PDF rasterizer on these files, never looked at any reader's code or output, and never opened golden_v1–golden_v28.**

## Conventions in expected.json

- `headings`: document order; the title first at level 1. Letterhead organisation names, box labels, form labels and table header cells are not headings.
- `key_sentences`: 4–10 full sentences of body text, exactly as visible, in reading order. No sentence carries a footnote marker (there are no footnotes in the set).
- `tables`: header row(s) first; a merged cell repeats its text in every grid cell it covers (two-level headers therefore give two header rows); total and section rows are rows of the same table; empty cells are `""`; a table that continues across pages is ONE table with its header given once even though Chrome repeats it on every page; right-to-left tables list cells in logical order, rightmost column first. A cell of several lines is joined with one space. `caption` is a real `<caption>`, or a unit/heading line the notes name, else null.
- `list_items`: level 0 = outermost. Markers that are TYPED in the text are included (followed by one space, except p05 and p07 where CJK markers are followed by no space); markers DRAWN BY CSS are not. Each document's notes say which is which.
- `furniture`: letterhead lines, running headers/footers (listed once) and page-number lines (once per page, as they read on that page).
- Text: whitespace runs collapse to one space; non-breaking spaces are spaces; right-to-left text is in logical order; Thai, Japanese and Chinese lines wrapped inside a sentence join with no space; letter-spaced text is given as plain words; all text is NFC. No soft hyphenation is used (Chrome does not hyphenate here); a compound with a real hyphen (e.g. "Varga-Mendes", "сдачи-приёмки") keeps its hyphen even if a line breaks after it.
