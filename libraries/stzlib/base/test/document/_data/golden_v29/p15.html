Tessellate Sync 4.2 Release Notes

Released 14 October 2026 · build 4.2.0.1187

Highlights

Version 4.2 introduces selective sync rules and a command-line report of sync conflicts. It also makes the first sync of large folders up to three times faster.

This release is a free update for all customers with an active subscription.

New features

Selective sync rules

You can now choose which files are synced by listing include and exclude patterns in a rules file. Patterns are matched relative to the root of the synced folder:

# .tessellate/rules.yaml
sync:
  include:
    - "projects/**"
    - "invoices/2026/*.pdf"
  exclude:
    - "**/node_modules/**"
    - "*.tmp"
  max_file_size: 2GB

Conflict report

The new tess conflicts command lists every file that changed on both sides, with the decision the client took:

$ tess conflicts --since 7d --format table
PATH                        LOCAL     REMOTE    ACTION
projects/atlas/plan.md      10:42:07  10:41:55  keep both
invoices/2026/0918.pdf      09:03:12  09:05:40  remote wins

Improvements

• Faster first sync on large folders:

– the initial scan now runs on four threads by default;

– unchanged files are skipped by size and modification time before hashing.

• The tray icon shows the number of files still waiting to upload.

• Proxy support:

– authenticated HTTP proxies are supported;

– the proxy can be read from the operating system settings.

Fixed issues

  • TS-2291: renaming a folder while offline no longer duplicates its contents.
  • TS-2304: file names with trailing spaces are synced on all platforms.
  • TS-2317: the client no longer stops when the disk is almost full; it pauses and warns instead.
  • TS-2342: shared links keep their expiry date after the file is edited.

Deprecated settings

The following settings still work in 4.2 but print a warning at start-up.

Setting Replacement Removed in
sync.ignore_file sync.exclude in rules.yaml 5.0
net.legacy_tls none; TLS 1.2 or later is required 4.3
ui.compact_tray ui.tray_style: compact 5.0

Upgrading

  1. Close the client on every device that uses the account.
  2. Install version 4.2 over the existing installation; settings are kept.
  3. Start the client and move any sync.ignore_file patterns into rules.yaml.

If you manage clients centrally, the MSI package accepts the same command-line options as version 4.1.
