# Golden set v24: 24 realistic PDF documents with known structure

This folder is an independent golden test set for scoring document readers (for example Docling and Softanza's native PDF reader). Each document `gNN` comes as three files:

- `gNN.html`: the source, written by hand;
- `gNN.pdf`: the source printed to PDF by headless Chrome;
- `gNN.expected.json`: the structure a perfect reader should recover: title, headings, key sentences, tables, list items, page furniture, languages, code blocks, and notes on the conventions used.

## How the set was made

- One author wrote all 24 documents in one session on 2026-10-29: every text, table and layout is new and invented for this set. The organisations, people, addresses and numbers are fictional.
- Each document was generated by a small Python script kept OUTSIDE this repository. The script writes the HTML and the expected JSON from the SAME strings, so the expected text is the text that was typed. Totals, shares and running balances are computed, not typed.
- Every HTML file was printed with `chrome.exe --headless=new --disable-gpu --no-pdf-header-footer --user-data-dir=<separate scratch profile> --print-to-pdf=gNN.pdf file:///.../gNN.html` (the installed Chrome, whose newest application folder is 156.0.8078.48). Page sizes and margins come from CSS `@page`; running headers, footers and page numbers mostly come from `@page` margin boxes, and a few documents place their furniture in the body.
- Page counts were read from the raw PDF bytes (`/Type /Page` objects and the `/Count` of the page tree; they agree for all 24 files). Page-number furniture lines in the expected files are derived from that count.
- Fonts: every family named in the CSS was checked against the fonts installed in `C:\Windows\Fonts` (none is a variable font). Before printing, each document's DOM was walked in headless Chrome to list every text run with its computed font, and every character was checked against that font's character map (margin-box text was checked against its own font). After printing, the `/BaseFont` names in the raw PDF bytes were compared with the fonts the CSS asked for. All 24 PDFs embed exactly the intended fonts, with no fallback font and no Type 3 font.
- Expected texts were cross-checked against the `innerText` of the author's own HTML in Chrome (never against any PDF): every heading, key sentence, list item and table cell occurs in the rendered HTML text.

## Independence

The author of this set never ran a PDF-to-text extractor, a document converter or a PDF rasterizer on these files, never ran or read any reader's code or output, and never opened golden_v1 to golden_v23 or their generator scripts. The PDFs were inspected only as raw bytes, for the page count and the `/BaseFont` names.

## Conventions used in expected.json

- `title` is the main heading and is also the first `headings` entry at level 1. A letterhead's organisation name is furniture, never a heading; table header cells and form labels are never headings.
- `key_sentences`: 4 to 10 full sentences of body text, exactly as visible, in reading order. Sentences with a footnote marker, lines that only introduce a list (ending with ':'), signature blocks and address lines are never used.
- `tables`: header row(s) first; a cell covered by a row or column span repeats the spanning text; a table that runs across a page break is one table with its header once; totals and section rows are rows of the same table; empty cells are `""`; cells of several lines are joined with one space; right-to-left tables list cells in logical order (rightmost column first). Key/value panels without a header row start with their first data row.
- `list_items`: the marker is included when it is typed in the text and omitted when CSS draws it; each document's notes say which is which. `level` 0 is the outermost level.
- `furniture`: one visible line per entry; a repeated running header or footer is listed once; page-number lines are listed once per page.
- Text normalisation: whitespace runs collapse to one space (non-breaking spaces U+00A0 and ideographic spaces U+3000 count as spaces); soft hyphens are dropped and hyphenated words broken at a line end are given whole; letter-spaced text is given as plain words; NFC; right-to-left text in logical order; in Chinese, Japanese and Thai a line wrapped inside a sentence joins with no space. Code is given exactly.
