Larkspur Queue Service: Deployment and Operations Guide

Document IDLQS-OPS-004Revision3.2
OwnerPlatform OperationsLast reviewed6 October 2026

1 Overview

Larkspur is the internal message broker used by the billing, notification and audit services. Each production cluster runs three brokers, and every partition is replicated to all three of them. This guide describes how to configure a broker, how to upgrade a cluster without downtime and what to do when the most common alarms fire.

2 Prerequisites

  • A host from the queue-node image, version 2026.09 or later, with:
    • at least 8 CPU cores and 32 GB of memory;
    • a dedicated NVMe volume of 500 GB or more for the data directory.
  • Membership of the lqs-operators group, which grants access to the lqsctl command.
  • An open change ticket for any work on a production cluster.

3 Configuration

The broker reads a single YAML file at start-up and does not reload it while running. A minimal production file looks like this:

# /etc/larkspur/broker.yaml
broker:
  listen: 0.0.0.0:7420
  data_dir: /var/lib/larkspur
  max_message_bytes: 1048576
  retention:
    hours: 72
    max_disk_gb: 400
replication:
  factor: 3
  ack: quorum
ParameterDefaultDescription
listen0.0.0.0:7420Address and port on which the broker accepts client connections.

4 Rolling upgrade

4.1 Before you start

Upgrade one broker at a time and wait until the cluster reports all partitions in sync before moving to the next one. A full upgrade of a three-broker cluster usually takes about forty minutes.

4.2 Steps

  1. Drain the broker so that it stops leading partitions:
    1. run the drain command shown below;
    2. confirm in the dashboard that its leader count has dropped to zero.
  2. Stop the service and install the new package.
  3. Start the service and check its status.
  4. Wait for re-synchronisation, then repeat from step 1 for the next broker.
$ lqsctl broker drain --id 2 --timeout 300s
$ sudo systemctl stop larkspur-broker
$ sudo dnf install larkspur-broker-3.2.1
$ sudo systemctl start larkspur-broker
$ lqsctl broker status --id 2
Warning: never stop a second broker while any partition is under-replicated. With a replication factor of 3 and quorum acknowledgement, losing two brokers makes the affected partitions read-only.
