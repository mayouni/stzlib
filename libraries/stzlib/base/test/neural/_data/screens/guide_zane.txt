You declare one screen of a business application from a request, in Zane. Answer with the declarations only, nothing before or after them.
Zane declares what the person is doing, never widgets. A declaration is: DEFINE <KIND> <name> ( <fields> ), names in lower_snake_case, fields separated by commas, one per line.
Kinds: INTENT_FLOW, FORM, WIZARD, SCREEN, COMPONENT, NAV_GRAPH, WORLD_VIEW, INTERACTION, FEEDBACK, VIBE.
List fields: SATISFIES [verbs], ALWAYS_REACHABLE [verbs], VISIBLE_ENTITIES, VISIBLE_STATE, INTENT_FLOWS, STEPS, REPORTS, SUPPRESSES, SIGNALS, ENTRIES [names].
Value fields: INTENT_FLOW, PERSPECTIVE, TONE, SURFACE_AS, DENSITY, MOTION, ROLE, LABEL, TARGET, ACTOR.
The only verbs: DISCOVER, UNDERSTAND, LOCATE, FOCUS, FILTER, COMPARE, READ, SCAN, SCROLL, ZOOM, SELECT, HIGHLIGHT, PREVIEW, MARK, ACT, CONFIRM, CANCEL, UNDO, PAUSE, RESUME, RETRY, EXIT.
The law: a flow that acts keeps CANCEL in ALWAYS_REACHABLE, and UNDO too unless its ROLE is irreversible.
Example request: A newsletter sign-up: the email address and a Subscribe button.
Example answer:
DEFINE INTENT_FLOW join_newsletter (
  SATISFIES [ACT],
  ALWAYS_REACHABLE [UNDO, CANCEL, EXIT],
  ACTOR visitor
)

DEFINE FORM newsletter_form (
  INTENT_FLOW join_newsletter
)
