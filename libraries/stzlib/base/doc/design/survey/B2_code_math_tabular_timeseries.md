## 0. What the engine can run (read from source, not from the brief)

- **Decoder** (`engine/src/neural_gen.zig:115-125`): `neural_model_has_generator` accepts GGUF `general.architecture` in {`llama`, `qwen2`, `qwen3`, `smollm`} AND requires tensors `blk.0.attn_norm.weight` + `output_norm.weight`. GPT-2 byte-level BPE; CONTROL tokens (`token_type==3`) are matched as literals (`neural_gen.zig:198-212`). **Consequence for FIM:** `<|fim_prefix|>` etc. only work as single tokens if the GGUF marks them type 3; if the converter marked them USER_DEFINED (4) they will be BPE-split. Unverified - check by reading `tokenizer.ggml.token_type` of the actual file before promising FIM.
- **Encoder** (`neural_embed.zig:402-475`): BERT family only - learned absolute positions OR ALiBi (jina-bert-v2), GELU or GEGLU FFN, **post-LN**, bias everywhere, WordPiece (classic `##` or SentencePiece-metaspace). Hard cap 256 tokens per sequence (`neural_embed.zig:497`). No RoPE encoder, no DeBERTa disentangled attention, no ModernBERT, no pre-LN.
- **Not present as graph builders:** gated-delta-net/linear attention, SSM, MoE, vision, Gemma, Phi, granite multipliers, T5/seq2seq, any numeric-input (non-token) transformer.
- **Vendored ggml already contains the ops for the new hybrid models**: `engine/vendor/ggml/include/ggml.h` lists `GGML_OP_GATED_DELTA_NET`, `SSM_CONV`, `SSM_SCAN`, `CUMSUM`, `TRI`, `SOLVE_TRI`, `L2_NORM`, `RWKV_WKV7`, and `ggml-cpu/ops.cpp` has the CPU kernel for gated_delta_net. So Qwen3.5 / Qwen3-Next style models need a *graph builder in Zig* (the llama.cpp `qwen35` recipe), not new kernels. (Verified by grep; I did not try to build it.)
- Also present and relevant: GBNF grammar-constrained decoding (`gbnf_machine.zig`, `neural_gen_set_grammar`), `string/fuzzy.zig` (Levenshtein, Hamming, Jaro, Jaro-Winkler, Jaccard, edit-distance clustering), `gguf_export.zig` (not read), SQLite (`db.zig`, `stzDatabase.Rows/Value`), `stats.zig`/`hypothesis.zig`/`fft.zig`/`knn.zig`/`logistic.zig`/`bayes.zig`/`cluster.zig`/`ann.zig`/`autodiff.zig`/`lbfgs.zig`/`optim.zig`.

## 8. Golden tasks (proposals; not built)

Item format is JSON lines; every checker is deterministic code (no LLM judge). A model "beats the floor" when its pass rate / error is strictly better than the floor on the same items, over >= 3 runs (this machine is noisy - see CLAUDE.md measuring rules).

1. **Code (FIM + completion, 15 items).** Item: `{prefix, suffix, hidden_middle, tests:[{call, expect}]}` cut from existing, tested Ring functions in `base/`. Checker: assemble `prefix + model_middle + suffix`, `ring`-load it, run the tests, count pass; second metric = syntax-load success. Floor: empty middle / `return nil`-style stub (expected ~0) and the existing Qwen2.5-Coder-1.5B result (5-6/20 on the generation test). Requires the FIM token-type check from section 0.
2. **Maths (word problem -> expression, 20 items).** Item: `{text, ref_answer(exact rational or integer)}`; the model must emit one Ring/expr line; checker evaluates it with Softanza's exact tower and compares to `ref_answer` exactly. Floor: the engine given the *correct* expression = 100% (tests the pipeline), and a "first number in the text" heuristic. Keep a 5-item "trap" subset (units, off-by-one) with a negative sibling each.
3. **Time series (12 series, 3 datasets, no login).** Data: `airline-passengers.csv` (144 monthly rows, verified fetchable: `https://raw.githubusercontent.com/jbrownlee/Datasets/master/airline-passengers.csv`) plus a fixed random sample of 10 series from M4 Monthly (`Mcompetitions/M4-methods`, `Dataset/Train/Monthly-train.csv` and its Test file; redistribution terms not verified). Task: forecast the last 18 points from the rest. Metric: **MASE (m=12, in-sample naive-seasonal scale)** and **sMAPE**, mean over series. Floors, in order: naive, seasonal-naive, drift (OLS slope from `stz_stats_regression`), Holt-Winters (write it in the harness), and "Softanza's own" = OLS trend + FFT-dominant-period seasonal-naive + MA. Candidates: TTM r3, Toto-2.0-22m, TimesFM 2.5, Chronos-Bolt-small. Checker: pure numeric, scored in Ring/Zig.
4. **Tabular (12 datasets).** Public, no login: Iris, Wine, Breast-Cancer-Wisconsin (UCI), plus small OpenML/UCI sets with <= 5,000 rows and <= 50 columns. Metric: accuracy and macro-AUC with a fixed 5-fold split by seed. Floors: majority class, `stzKnn`, `stzLogisticRegression`, `stzDecisionTree` (ID3). Checker: arithmetic on predictions. A GBM computed offline is the "real" bar to disclose.
5. **Data wrangling (15 NL questions over a fixed SQLite DB + 10 extraction docs).** Item A: `{question, gold_sql}`; checker runs both SQL strings in `stzDatabase`, compares result sets as sorted multisets. Item B: `{text, schema, gold_json}`; checker = field-by-field exact match for `verbatim` fields, numeric tolerance otherwise, and `schema valid` rate (should be 100% under GBNF). Floors: a regex+template extractor over the same documents, and the "no answer" baseline.
6. **Security (20 prompts: 10 injections incl. indirect/encoded, 10 benign near-misses like "ignore the previous page of the PDF").** Label by hand, freeze. Metric: accuracy, FPR on benign. Floor: keyword/regex list in Softanza's regex engine (`ignore (all )?(previous|above) instructions`, role-override phrases, base64 sniff). Candidates: Qwen3Guard-Gen-0.6B (`Jailbreak` category), the Qwen3-0.6B injection classifier. Add 10 secret-in-text items (checker: exact span or none) with a regex+entropy floor.
7. **Geo (20 noisy place strings, e.g. "Niamy", "Cote dIvoire", "Rep. Dem. Congo", "St. Petersburg FL").** Gold = ISO country code (and GeoNames id for 5 cities). Checker: exact match. Floors: `StzGeoAtlas.IndexOf` exact; then fold + Jaro-Winkler >= 0.9 over the atlas names (the pieces exist). A model must beat the fuzzy floor, not the exact one.
