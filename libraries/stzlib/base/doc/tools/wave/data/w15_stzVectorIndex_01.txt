init | Stores the vectors of a corpus to be searched by nearest neighbour; the search structure itself is built at the first search. | nothing; the object is built | paVectors=a non-empty list of vectors, each a list of numbers, all of the same length | Search, SetMetric | an empty list, a list whose items are not lists, or vectors of different lengths raises an error naming the problem |
SetTrees | Sets how many random trees the index grows; more trees find the true neighbours more often and take more memory. | the same object, so calls chain; the default is 10 | n=the number of trees, at least 1 | SetSeed, RecallAgainstExact | | a value below 1 raises "SetTrees: at least one tree."; the index is dropped and rebuilt at the next search, so it can be called at any time
SetMetric | Chooses how closeness is judged: :Euclidean compares positions, :Cosine compares directions after scaling every vector to length 1. | the same object, so calls chain; the default is :Euclidean | pcMetric=:Euclidean or :Cosine | CosineFromDistance, Metric | | any other value raises "SetMetric: :Euclidean or :Cosine."; text embeddings almost always want :Cosine; the index is rebuilt at the next search
SetSeed | Sets the seed of the random trees so that a build, and any recall figure, can be repeated. | the same object, so calls chain; the default is 42 | n=the seed number | SetTrees, RecallAgainstExact | | the index is rebuilt at the next search
Trees | Returns the number of trees the index will grow. | a number | | SetTrees | |
Metric | Returns the metric in use, in lowercase: "euclidean" or "cosine". | a text | | SetMetric | |
Count | Returns how many vectors the index holds. | a number | | Dimensions | |
Dimensions | Returns how many components each vector has. | a number | | Count | |
Search | Returns the k stored vectors nearest to a query, nearest first, with their squared distances, from an approximate search. | a list of [ index, distance ] pairs; fewer than nK when the index is smaller | paQuery=the query vector, as many numbers as the stored vectors have; nK=how many neighbours to return, at least 1 | SearchWithBudget, SearchExact, RecallAgainstExact | | indexes count from 1; the distance is squared Euclidean (in :Cosine mode 2 - 2 x cosine), so 5 apart reads 25; the distances are exact, and an approximate answer can only omit a true neighbour; Nearest is the same method
SearchWithBudget | Returns the k nearest vectors like Search, with the number of candidates examined stated: a bigger budget finds more of the true neighbours. | a list of [ index, distance ] pairs, nearest first | paQuery=the query vector; nK=how many neighbours to return; nBudget=how many candidates to examine, 0 for the default | Search, RecallAgainstExact | | the budget is the dial between speed and recall
SearchExact | Returns the k nearest vectors by scanning every stored vector, the ground truth against which Search is judged. | a list of [ index, distance ] pairs, nearest first | paQuery=the query vector; nK=how many neighbours to return | Search, RecallAgainstExact | | the cost grows with the corpus; for a large Euclidean corpus the scan may run on the GPU, with distances in single precision; NearestExact is the same method
RecallAgainstExact | Returns the share of the true k nearest neighbours that the approximate search finds, over a set of queries; 1 means none missed. | a number from 0 to 1 | paQueries=a non-empty list of query vectors; nK=how many neighbours to compare; nBudget=the candidate budget, 0 for the default | SearchExact, SearchWithBudget | | measure it on your own vectors before trusting a budget; a query of the wrong width or an empty list raises an error
CosineFromDistance | Returns the cosine similarity that a stored distance stands for, 1 - distance / 2. | a number from -1 to 1 | nDist=a distance returned by a search of a :Cosine index | SetMetric, Search | | on a :Euclidean index it raises "CosineFromDistance: only meaningful for a :Cosine index."
