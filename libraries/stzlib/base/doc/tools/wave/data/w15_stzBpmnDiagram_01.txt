# w15 stzBpmnDiagram -- Name | brief | returns | params | see | warning | note
init | Builds a BPMN layout over a stzWorkflow, with no endings marked yet. | nothing; the object is built | poWorkflow=the stzWorkflow whose steps are laid out | MarkEnding, LayoutDigest | | the diagram reads Steps() and Transitions(), not the states: a workflow built only with AddStateXTT has no steps and lays out nothing
MarkEnding | Declares a step to be a process ending, drawn as a marker instead of a node. | nothing; the ending is recorded. MarkEndingQ returns the diagram for chaining | pcName=the id of the step that ends the process; pcKind=terminal or suspension, case ignored; pcOutcome=the outcome label such as success or fail, case ignored | MarkResume, IsEnding, EndingKind | | the kind and outcome are stored in lower case; marking a name again adds a second record and the first one is the one read back
MarkResume | Declares that a suspension ending re-enters the process at a step. | nothing; the resume is recorded | pcEnding=the name of a suspension ending; pcTargetStep=the step where the process resumes | MarkEnding, LayoutDigest | | the return arrow only appears in the layout when some step arrives at that ending
Layout | Places every step in a column and a row by the written BPMN layout law, once. | nothing; the placement is kept inside the diagram | | LayoutDigest, EntryStep | | a second call does nothing until MarkEnding or MarkResume resets it; an empty entry step leaves the layout empty
EntryStep | Returns the id of the step nothing points at, or the first declared step. | the step id as text; an empty text when the workflow has no steps | | ArrowsFrom, Layout | | a workflow built only with AddStateXTT answers an empty text, because it reads Steps()
ArrowsFrom | Returns the arrows leaving a step, each as label, target and exceptional flag. | a list of [ label, target, exceptional ] triples; [ ] when none leave | pcStep=the id of the step the arrows leave | EntryStep, Layout | | it reads the transitions when the workflow has any, else its plain edges with their label and a flag of 0
IsEnding | TRUE if a step has been declared a process ending. | TRUE or FALSE, as 1 or 0 | pcName=the step id to test | MarkEnding, EndingKind | |
EndingKind | Returns whether an ending is a terminal or a suspension. | the kind as text; terminal for a name that is not an ending | pcName=the ending to ask about | MarkEnding, EndingOutcome | | the answer for an unknown name is terminal, not an empty text
EndingOutcome | Returns the outcome label an ending was declared with. | the outcome as text, in lower case; an empty text for a name that is not an ending | pcName=the ending to ask about | MarkEnding, EndingKind | |
EndingId | Returns the element id of the nth marker drawn for an ending. | the id as text | pcName=the ending name; n=the arrival number, from 1 | EndingKind, LayoutDigest | | the id is terminal_ or suspended_ followed by the name, with __n added from the second arrival on
KindOf | Returns the BPMN node kind of a step from its type property. | one of gateway, timer-wait, event-wait, compensate, human or invoke, as text | pcStep=the step id to classify | EndingKind, Layout | | a decision or gateway type gives gateway, usertask or an assignedTo gives human, and anything else is invoke
LayoutDigest | Returns the conformance record of the layout: entry, nodes, endings and arrows, one sorted line each. | a multi-line text starting with LAWVER 1.0.0 | | Layout, EntryStep | | lines are sorted by character code; a workflow with no steps gives the header and an E line only
