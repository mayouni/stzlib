init | Builds a new twin hub of its own, with a clock, a set of customers and 50 000 000 virtual francs on the platform's account. | nothing; the object is built | | Id, AdoptHub, Request | the twin holds virtual francs and takes no fee, montantFrais is absent because the participant's fee is the participant's contract | the state lives in process-wide tables and the object carries only the hub number, so a copy of the object is the same hub
IsSandbox | Answers TRUE always, so that a registry takes the twin for a fake and refuses it in a production phase. | TRUE | | Id | stzServiceRegistry
Id | Returns the number of the hub this object is a face of. | a number, 1 for the first hub of the process | | AdoptHub, init
AdoptHub | Points this object at a hub that already exists, so that two objects drive the same twin. | the object itself, so calls chain | pnId=the number a hub's Id answered | Id | the HTTP front uses it to reach the twin it serves
Request | Answers one call of the hub contract in process, as [ status, body ], the method the port and the live adapter both speak. | a list of two items, the HTTP status and the body as a list, or an empty text for a 204 | pcMethod=GET, POST, PUT or DELETE; pcPath=the contract path such as /paiements-envoyes or /comptes; paQuery=a list of [ key, value ] pairs for paging and filters, a non-list meaning none; paBody=the body as a list, a non-list meaning none | Now, AdvanceSeconds, stzPispiHttpAdapter | each call moves the twin's clock forward one second; a missing resource is a 404 problem, a field the schema does not know a 400, a txId used twice answers 200 with statut REJETE and statutRaison DU03, and over the quota a 429 | the twin enforces what the reference enforces, so that code which pays twice or sends an unknown field fails in a test, but it is a model of the contract and not the hub: the live adapter has not been run against the BCEAO's sandbox, so how closely the two agree is unperceived
Now | Returns the twin's clock as an ISO timestamp, which starts at 2026-10-05T09:00:00.000Z. | a text such as 2026-10-05T09:00:26.000Z | | AdvanceSeconds, Request | the clock moves only by one second per request or when asked, never with the wall clock, so a test never waits twenty seconds
AdvanceSeconds | Moves the twin's clock forward and settles every payment that has come due, a pending one becoming final after 20 seconds. | the object itself, so calls chain | pn=the number of seconds to move the clock forward | SettleEverything, Now | the webhooks the settlement announces are queued if a registered webhook listens to them
SettleEverything | Makes every pending payment and request final now, as if 20 seconds had passed. | the object itself, so calls chain | | AdvanceSeconds, NumberOfPayments
SetRateLimit | Sets the hub's quota, so that calls beyond it answer a 429 problem. | the object itself, so calls chain | pnPerMinute=how many calls the hub accepts in a minute of its own clock; pnPerDay=how many it accepts in a day | Request, AdvanceSeconds | the minute window follows the twin's clock, so advancing it past a minute lifts the limit
Alias | Returns the PI-SPI alias, a UUID, of one of the twin's customers by short name: business, fatou, boutique, kdi, blocked or stubborn. | a text; a name the twin does not know comes back unchanged | pcWho=the customer's short name, matched without regard to case | BusinessAlias, AddCounterparty, SetCounterparty
BusinessAlias | Returns the alias of the platform's own account on the twin. | a text, a UUID | | Alias, BusinessAccount
BusinessAccount | Returns the account number of the platform's own account on the twin. | a text, the same for every hub | | BusinessAlias, Balance
Balance | Returns the platform's balance in francs, 50 000 000 at birth. | a number | | SimulateIncomingPayment, NumberOfPayments | a payment sent lowers it at once and a payment received raises it at once, before any settlement
SetCounterparty | Sets how one customer's side answers: a payment, a request to pay and a cancellation. | the object itself, so calls chain | pcWho=the customer's short name or alias; pcPay=ok or the ISO reason code that rejects a payment to this customer, such as AM04; pcRtp=pay or the reason code that declines a request to pay; pcCancel=accept or the reason code that refuses a cancellation | AddCounterparty, Alias | raises an error for a customer the twin does not know, naming it; a payment to a customer set to AM04 ends REJETE with that reason
AddCounterparty | Adds a customer to the twin that accepts every payment, request and cancellation until SetCounterparty says otherwise. | the object itself, so calls chain | pcAlias=the new customer's alias, a UUID text; pcName=the name shown to the platform; pcCountry=the two-letter country code such as NE; pcCategory=the category letter, P, B or C as the seeded customers carry | SetCounterparty, SimulateIncomingPayment | the customer is known by its alias, not by a short name
SimulateIncomingPayment | Makes a customer pay the platform, raising the balance at once and queueing a PAIEMENT_RECU webhook. | the end2endId of the payment, a text of 35 characters | pcWho=the customer's short name or alias; pnMontant=the amount in francs; pcMotif=the label the payer wrote, an empty text for none | SimulateIncomingRequest, Balance, Deliveries | raises an error for a customer the twin does not know; the webhook is queued only if a registered webhook listens to PAIEMENT_RECU, so a twin with no webhook shows no delivery
SimulateIncomingRequest | Makes a customer ask the platform to pay, queueing an RTP_RECU webhook. | the end2endId of the request, a text of 35 characters | pcWho=the customer's short name or alias; pnMontant=the amount asked in francs; pcMotif=the label the customer wrote | SimulateIncomingPayment, Deliveries | raises an error for a customer the twin does not know; the webhook is queued only if a registered webhook listens to it
SimulateCancellationRequest | Makes a customer ask to cancel a payment the platform received, queueing an ANNULATION_DEMANDE webhook. | the object itself, so calls chain | pcEnd2EndId=the end2endId of a payment the platform received; pcMotif=the reason the customer gives | SimulateIncomingPayment, FailNextAnswer | raises an error when the id is not a received payment
FailNextAnswer | Makes the hub reject the next answer the platform gives to a request to pay or to a cancellation. | the object itself, so calls chain | | SetCounterparty, SimulateIncomingRequest | it exists so that RTP_REPONSE_REJETE and ANNULATION_REPONSE_REJETE can be seen
NumberOfDeliveries | Returns how many signed webhooks this hub has queued since birth, delivered or not. | a number | | NumberOfUndelivered, Deliveries
