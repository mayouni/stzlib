init | Builds an extractor for the named variables and sets Ring's display precision to 4 decimals until BraceEnd puts it back. | nothing; the object is built | p@aVars=the list of variable names the expressions may use | extract, BraceEnd | the precision is global to the program and stays at 4 unless the object is used in a brace or BraceEnd is called
setVariableNames | Replaces the variable names the extractor knows. | nothing | p@aVars=the new list of variable names | VarNames, init
setPerturbationDelta | Sets the small step by which the numerical method nudges a variable; the default is 0.001. | nothing | pnDelta=the step, a small positive number | numericalDerivative
BraceEnd | Puts Ring's display precision back to what it was when the extractor was built, at the closing of a brace. | nothing | | init | called by hand it has the same effect
extract | Returns the coefficient of one variable in an expression, read term by term when the expression is plain linear. | a number; 0 when the name does not appear | cExpression=the expression text, such as 5*x + 3*y - 2*z; _cVarName_=the variable whose coefficient is wanted | extractAllCoefficients, trySimpleExtraction, numericalDerivative | an expression with /, pow, sqrt, max, min or abs raises R42 Error in eval() function today, because evaluateExpression builds an empty formula (see it); the plain path reads variable names as substrings, so for 5*xx + 2*x it answers 5 for x, and a repeated variable gives only its first term | ExtractCoefficient and ExtractCoeff are the same call
trySimpleExtraction | Returns the coefficient when the expression is plain linear, and an empty text when it is not, which tells extract to differentiate. | a number, or an empty text for a non-linear expression | cExpression=the expression text; _cVarName_=the variable | extract, isSimpleLinearExpression | the same substring reading of names as extract
normalizeExpression | Returns the expression with its spaces and tabs removed. | a text such as 5*x+3 | cExpression=the expression text | trySimpleExtraction
isSimpleLinearExpression | TRUE if the expression has none of min(, max(, abs(, sqrt(, pow(, a slash or a caret, so it can be read term by term. | 1 or 0, numbers | cExpression=the expression text, already without spaces | trySimpleExtraction, normalizeExpression
extractLinearCoefficient | Returns the number before the star in the first term that mentions the variable; 1 or -1 when none, 0 when no term. | a number | cExpression=the expression text without spaces; _cVarName_=the variable | trySimpleExtraction | the first term containing the name as a substring wins, so xx is taken for x
numericalDerivative | Raises error R42 today instead of returning the slope of the expression along one variable at the test point 10. | nothing; it raises | cExpression=the expression text; _cVarName_=the variable to nudge | extract, setPerturbationDelta, evaluateExpression | every call raises R42 Error in eval() function (checked on x/8 + y/4 and pow(x, 2)), because evaluateExpression builds an empty formula | the intended result rounded as roundCoefficient does
createTestValues | Returns the point where non-linear expressions are tested: every variable at 10. | a list of [ name, 10 ] pairs | | numericalDerivative, evaluateExpression
evaluateExpression | Raises error R42 today instead of returning the value of an expression at a point. | nothing; it raises | cExpression=the expression text; aVarValues=a list of [ name, value ] pairs | numericalDerivative, createTestValues | the variables are replaced by calling ManyReplaced with a list of new texts, which takes ONE new text and returns an empty text, so the evaluated formula is empty and eval fails with a syntax error (checked on x + y and x + 1)
roundCoefficient | Returns a coefficient rounded to six decimals, as a whole number when it is within a millionth of one. | a number | _nCoeff_=the raw number to tidy | numericalDerivative | | 2.0000001 gives 2
VarNames | Returns the variable names the extractor knows. | a list of text | | setVariableNames | | VariableNames is the same call
extractAllCoefficients | Returns the coefficient of every known variable in the expression, in the order of the names. | a list of numbers | cExpression=the expression text | extract, VarNames | the same limits as extract for non-linear expressions
validateExpression | Returns 0 for every expression today instead of telling whether it can be evaluated. | 0, a number | cExpression=the expression text | evaluateExpression | it calls createTestValues with an argument that method does not take, which raises inside its try, so the answer is always 0 (checked on x + 1 and x + y)
